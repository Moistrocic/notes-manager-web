# 笔记管理面板 · notes-manager-web

一个自托管的 Markdown 笔记管理面板：笔记以普通 `.md` 文件直接存放在 OpenList 目录里，
可以用你自己的 OpenList 账户登录；服务器上没装 OpenList 时也能正常运行。
打开「博客」之后，站点根 `/` 会变成一页只展示已发布笔记的公开博客。

## AI 开发

> 这个项目完全由 AI 开发：人类负责提需求、验收与决策。所以注释、测试与提交信息都写得比较"自解释"。
> 动手前先读 [AGENTS.md](AGENTS.md)：那里写着「做完就提交」这条铁律、代码地图和几个已知的坑。

**改完必须跑**（这一条命令覆盖 CI 会跑的全部检查）：

```bash
npm run check     # check:repo + typecheck + build:server + test:server + check:web
# 动过 scripts/*.sh 再补：
npm run test:installer
shellcheck --severity=warning scripts/install.sh scripts/uninstall.sh scripts/test-install.sh scripts/doctor.sh
```

**约定**

- 提交信息用 Conventional Commits，一个提交只做一件事；**每完成一个功能或修好一个缺陷就提交一次**
- 运行时状态一律不入库（`.env`、`data/`、`sessions.json`、`settings.json`）；
  `npm run check:repo` 会按路径和文件内容双重拦截
- `openlist/` 只是阅读用的只读参考，不修改、不提交
- 用户可见的行为要有断言（`web/dom-check.tsx` 或 `scripts/test-server.mjs`），不要只靠手点。
  在 jsdom 里断言「某个东西消失了」要留出时间：菜单、弹窗、首页 / 面板的切换都包在
  AnimatePresence 里，而 jsdom 不跑动画帧，退出动画要几百毫秒才落地（dom-check 的
  `settled()` 就是等这一步的，别用一次 `flush()` 去问）
- 同一个颜色 / 字体 / 尺寸只写一处，别在仓库里出现两份

**两个坑**

- `scripts/test-install.sh` 用 `awk` 从 `install.sh` 里按函数名抽取真实函数体执行，
  判据是"第一个第 0 列的 `}`"，所以内嵌的 shell / JS 片段必须缩进，否则抽取会中途截断
- `.gitignore` 里的模式要加前导 `/`：曾经写了不带斜杠的 `openlist/`，
  把 `server/src/integrations/openlist/` 一起忽略了，源码没进仓库

## 功能介绍

**笔记**

- 普通 Markdown 文件 + YAML front matter（标题、标签、置顶、收藏、颜色），
  可直接在 OpenList 里查看、编辑、同步
- 手动放进目录的 `.md` 会被自动识别，没有 front matter 也能解析
- **标题就是文件名**：改标题会真的重命名那个文件——`.md` 是这样，图片和其它文件也是这样；
  地址栏里的深链跟着换到新路径
- **输入不写盘**：正文与标题都只在编辑器失焦、或按 `Ctrl/⌘ + S` 时保存。
  以前每敲一个键就发一次请求，回包带着旧标题落回输入框，正在打的字被盖掉——
  看起来就像改名失败；现在输入只改本地状态，状态指示会显示「未保存」
- 编辑器 / 分栏 / 预览三种模式，分隔条可拖动、双击恢复居中
- **分栏时有一枚「同步滚动」**（在头部模式切换的右边）：打开后两侧一起走——按**源码行**同步。
  为什么不是百分比：同一行源码在预览里可能是一行标题、也可能是半屏的图片，两侧的高度本来就
  不是一回事，按比例走必然越走越偏（笔记越长差得越远）。所以预览里每个块都记着它来自哪几行
  源码，一侧动了就把「读到第几行」映射到另一侧的对应位置——这也是 VS Code 那个 markdown
  预览的做法。默认关闭，选过之后记住；只有分栏模式有这个按钮，单独一个栏位没有第二个滚动条
  要对齐。
  点大纲或锚点跳转时不会同步：那是预览自己在动，拽着编辑栏一起动只会两边打架；
  跳完之后，下一次滚动按当下的位置重新对齐。编辑栏底部那段打字余量也不影响对齐——
  它不是要读的内容，终点就是正文最后一行的终点，两侧一致
- **图片直接看，不当文本编辑**：图片文件在编辑器的位置显示图片本身（由服务端按路径直出），
  没有三态切换、没有元数据栏、没有大纲——对一张图来说这些控件一个也用不上；
  改名、移动、删除、下载照旧
- **其它格式不硬撑预览**：显示「暂不支持预览这种格式」和一个下载按钮，而不是把二进制
  当文本塞进编辑器
- 正文区右键是面板自己的菜单（撤销 / 重做 / 剪切 / 复制 / 粘贴 / 全选 /
  加粗 / 斜体 / 标题 / 引用 / 列表 / 链接…），不再弹出浏览器菜单；
  markdown 快捷工具栏整行已删除，这些动词都收进右键菜单，正文一行都不被占用
- 实时预览（GFM、表格、任务列表），代码块按语言高亮，140+ 种语法包按需加载
- **笔记里的图片**：`![图](./img/a.png)` 的相对路径按**笔记自己所在的目录**解析
  （`./` 可省、`../` 可以往上走），以 `/` 开头当作笔记根之下的路径，
  `http(s)://`、`//`、`data:`、`blob:` 原样不动。解析出来的路径交给 `/api/notes/file`
  直出，所以图片与笔记走同一套存储：不论是本地磁盘、OpenList，还是某个 OpenList 账号，
  取图的路都一样
- **只写了图片地址也会显示图片**：一段文字里出现的图片链接（或从 JSON 里粘来的
  `{"url":"https://…/a.png"}`，渲染器会把它变成链接、还把结尾的引号花括号吞进地址里）
  会在文字后面直接画出那张图，链接本身也被改回干净的地址；代码块里的地址保持原样，
  图统一画在**代码块下方**（同一地址只画一次，最多 12 张）——代码是代码，图是图。
  外部图片一律带 `referrerpolicy="no-referrer"` 与 `loading="lazy"`：
  有些站点只在自己页面上出图，带上来源就会被拒绝，索性不带
- 编辑与预览共用同一套代码配色（VS Code Dark+ / Light+），字体字号行高也一致
- 大纲面板可折叠；点击大纲同时滚动编辑区与预览，并在预览中高亮落点
- 全文检索、标签筛选、嵌套文件夹（可建 `a/b/c` 多级）、置顶 / 收藏 / 颜色标记
- **目录树是唯一的笔记列表**：按笔记在磁盘上的真实层级排列，一眼看出「这篇在哪」。
  卡片 / 网格视图与切换按钮已删除——它们只能回答「有哪些笔记」，那是搜索框的问题
- **行的操作都在右键菜单里**：笔记有打开 / 重命名 / 移动到文件夹 / 置顶 / 收藏 /
  删除（移入回收站）；图片和其它文件有打开 / 重命名 / 移动到文件夹 / **下载** / 删除
  （它们没有「置顶 / 收藏」——那些字段本来就不属于一张图）；文件夹有新建子文件夹 /
  重命名 / 移动到文件夹 / 删除，并且只有顶层文件夹才提供「新建顶层文件夹」
  （子文件夹的兄弟就在它自己那个目录里）。悬浮行内工具栏已删除——它出现的位置，
  正好是一行的标题。菜单本身是**不透明的深色底**（浅色主题下是纯白）：它盖在正文或图片上，
  半透明的话底下的字会透上来，读起来是两层文字叠在一起
- **空白处右键**就是「新建顶层文件夹」：树里还没有任何东西时也有地方可以动手，
  不必先找到某个文件夹行。**最后一行的下方也算空白**——树铺满剩下的高度，
  而不是把底下那片区域让给别的东西
- **点一下就是点一下**：手指几乎没动就松开，那还是普通的点击——打开笔记、展开文件夹，
  和以前一样
- **按住不动 300ms 进入多选**：这一行被选中（高亮 + 勾选标记），行上也标出它是被按住的那一行。
  之后**单击**另一行把它加进来，再点一次拿出去；`Ctrl/⌘ + 点击` 同样是一次切换，
  不会打开笔记。**列表上方不再有批量条**：多选只体现在行自己的高亮上，
  批量动作在**右键菜单**里（下载 N 项 / 移动 N 项 / 删除 N 项 / 取消选择）——
  数量就写在条目上，选中了几行一眼能看到，也省掉了压在第一行笔记上的那条横杠。
  松手那一下的点击可能落在行以外的地方，那一下不算「点了空白」，不会把刚选好的清掉。
  `Esc` 或点空白处退出多选。
  批量下载和单个下载一样，是让浏览器逐个保存文件本身（文件夹没有字节可下载）
- **按住之后一动就是拖动**：手指移动超过一点点（8px）就进入拖动，指针旁边浮出一张小卡片
  写着这一行的名字（多选状态下拖动则写「N 项」）。拖到另一个文件夹（那一行会亮起来）
  或最后一行下方的空白（等于根目录），树顶浮出「松开移动到 X」的提示
  （它不占高度，不会把行从指针底下顶走），松手即移动——不再弹一次
  「移动到哪个目录」的对话框，因为这个拖动已经把答案给了。
  **拖动全程不会打开多选**；真的移动了以后选择立刻清空、高亮随之消失——
  行已经不在原来的地方，留着选择只会指向旧路径。落在放不了的地方（别的笔记行、树外）
  或中途取消，就什么都不动，按下时选中的还是那几行。
  文件夹不会被放进它自己、它的子目录，或它已经在的那个目录
- 排序：默认按**标题**升序，可切「最近更新 / 创建时间 / 字数」，方向另有升 / 降两个按钮
  （一眼看出当前方向，而不是从一个图标去猜）
- **上传不再只收 markdown**：任意文件都能传，空文件也能传，文件名与扩展名原样保留；
  `.md` / `.markdown` / `.txt` 是笔记（标题取文件基本名，不再拿正文里第一个一级标题），
  图片按图片处理，其余都算「其它文件」——目录树本来就把目录里的每个文件列出来，
  行首的图标（笔记 / 图片 / 文件）就是它属于哪一类
- 新建笔记与上传文件都先弹一个对话框选**目标目录**（空选项表示根目录），再动手：
  目录是个选择，不是从上一次点击里猜出来的
- 回收站：删除 → 撤销 → 恢复 → 彻底删除；笔记、图片和其它文件都在同一个回收站里，
  恢复时回到它原来的目录
- 深链与锚点：管理面板整个在 `/manager/` 之下，笔记的地址就是它在存储里的路径——
  `/manager/public/Notes/Readme.md#11-分层`，可以直接分享；笔记内的
  `[文字](#锚点)` 与 `[文字](./另一篇.md)` 均可点击跳转。站点根 `/` 是**博客**
  （见下一节），博客关掉时它连同 `/notes/…` 一起跳回 `/manager/`。
  分成这些地址是为了各归其位：链接指向谁就打开谁，首页不会被面板顶掉
- 命令面板（`Ctrl/⌘ + K`）与快捷键：`Ctrl/⌘ + S` 保存、`Ctrl/⌘ + E` 切换三种模式、
  `Ctrl/⌘ + B` 显示 / 隐藏列表、`Alt + N` 新建笔记（直接创建，不走目录弹窗）、
  `Esc` 关掉最上层的弹层或退出多选
  （搜索框的 `/` 快捷键已删除：它会在打字时抢走焦点）
- 专注模式、Toast 撤销
- 左侧栏可整体隐藏；窄屏变成抽屉，左缘的把手是随时回到列表的路

**博客**

- **站点根 `/` 就是博客**：设置里打开「开启博客」之后，`/` 是博客首页（已发布文章的卡片），
  单篇的地址是 `/notes/<笔记在存储里的路径>`——例如 `/notes/public/Notes/Readme.md#11-分层`，
  可以直接分享给没有账号的人。**关掉之后**，`/` 与 `/notes/…` 都会跳到 `/manager/`
  （管理面板的登录页）：这两个地址本来就属于面板，不该留一页没人维护的东西在那。
- **只有被标记发布的笔记才会上博客**：发布信息写在笔记的 front matter 里
  （`blog` / `blogAt` / `blogTitle` / `blogSummary`），所以删除笔记时它随之消失，
  移动或重命名笔记时它自动跟着走。怎么发布见下一节「发布」。
- **卡片按发布时间倒序**：最新发布的排在最上面。卡片显示发布时设置的标题与简介；
  没设置就回退到笔记自己的标题与正文开头自动生成的一段。
- 卡片上有标题、开头一段、以及右上角的发布时间与修改时间。开头一段是 **markdown 渲染**的，
  所以列表、加粗、斜体都还在，只有链接被去掉——整张卡片本身就是一个链接，
  链接里再套一个链接是点不动的。点卡片打开单篇；它是个真的 `<a>`，
  所以也能在新标签页里打开、或者直接复制地址。
- 单篇页：标题、发布时间、修改时间、字数，正文就是这篇笔记（GFM、代码高亮、表格……
  和面板里预览看到的一致）；右边是文章大纲，**只有一个把手**控制它的显隐——
  面板的大纲自带一个收起按钮，那是两个控件管同一件事，这里只留一个。
  带 `#锚点` 的深链会直接滚到那一节，并高亮一下落点。
- **公开接口只开三扇门**：`/api/blog`（首页数据）、`/api/blog/post?path=`（单篇）、
  `/api/blog/file?path=`（取图）。它们**只放行已发布的笔记，以及这些笔记引用到的文件**：
  没发布的笔记、目录里的其它文件、以及 `..` 之类想爬出白名单的路径都拿不到。
- 博客里的图片走 `/api/blog/file`：访客没有账号，而面板的 `/api/notes/file` 会先问「你是谁」；
  面板里预览同一篇笔记时仍然走 `/api/notes/file`，两边各走各的门。
- 博客页面不读管理面板的 store：它是给没有账号的人看的，内容用自己的公开接口取，
  面板里的笔记列表、登录状态一概不参与。

**发布**

- **入口有两个**：左侧列表顶部（回收站旁边）的「发布管理」，和**右键一篇笔记 → 发布管理**。
  前者是全部笔记的表格，后者直接打开那一篇的设置。
- **单篇的发布设置**：「发布到博客」开关决定这篇上不上博客；「博客标题」「博客简介」是给卡片用的
  ——**留空就用笔记自己的**（标题回退到笔记标题，简介回退到正文开头自动生成的一段）。
  简介左边写、右边**实时渲染**成卡片上的样子，支持 Markdown。
- **发布管理是一张表**：一行一篇用过发布设置的笔记，列是状态（已发布 / 不发布）、发布时间、
  文件路径、文件名称、卡片标题、简介。每格只占一行，所以**双击一行**能看完整内容。
  行尾两个按钮：**编辑发布信息**（打开与单篇相同的设置弹窗）与**删除发布信息**。
- **「取消发布」和「删除发布信息」不是一回事**：取消发布只是把 `blog` 关掉——笔记还在表里，
  状态显示「不发布」；删除发布信息才把四个发布字段一起清掉，这篇笔记从此不出现在发布管理里。
  删除**不会**动笔记文件，确认框里也是这么写的。
- 发布设置只碰 front matter，笔记的正文、文件名、位置都不动；反过来，移动或重命名笔记时
  发布信息跟着走，删除笔记时一起消失——它就存在那篇笔记里。

**外观**

- 深色 / 浅色主题，动态极光背景，玻璃拟态面板，全流程过渡动画
- 字体：内置 Cascadia Code（代码字体默认就是它，无需联网下载）；管理员还可上传
  woff2 / woff / ttf / otf，分别指定界面字体与代码字体，重启后依然生效
- 壁纸：图片链接 / 本地图片或视频 / 本地壁纸库三种来源，可调模糊、暗度、缩放
  - 壁纸库会从你授权的目录里自动定位 Wallpaper Engine 的壁纸总文件夹，
    按每个壁纸一格展示预览图
  - 场景壁纸（`scene.pkg`）默认**合成一张完整背景图**：它旁边的 `preview.jpg` 只是方形
    缩略图，真正的宽幅画面在容器里，由各图层合成得到（在后台线程完成，结果会缓存）
  - 也可以打开「动态场景壁纸」，让场景在浏览器里**实时渲染**（有动画，较耗电）
- 加载服务器设置好的壁纸时，屏幕正上方显示一张进度卡：下载容器阶段有百分比（静态合成与实时渲染都是），
  之后的解析 / 合成阶段换成走动进度条并说明在做什么——那几步是库内部的单次调用，测不出百分比，
  所以不编数字；浏览器缓存命中时不会闪一下
- 壁纸只存在浏览器本地，不上传服务器

**与 OpenList 的联动**

- 用 OpenList 账户登录（支持两步验证）；登录后所有文件操作都用你自己的令牌，
  OpenList 侧的权限与基础路径限制完全生效
- 目录里的文件就是笔记、图片和其它文件本身：新建、上传、重命名、移动、删除、回收站
  都直接作用于该目录（改标题就是重命名文件，两者不会是两份不同的名字）；
  图片与笔记同一个读取接口，取图不需要额外的图床
- 回收站是 OpenList 目录下的 `_trash` 文件夹，不是隐藏数据库
- 没有写权限的账号自动进入只读模式；只读云盘也能正常浏览
- 每个用户可以用独立的子目录（`OPENLIST_PER_USER`），互不可见
- 本地管理员要访问 OpenList 存储，需要一个 API 令牌（OpenList →「设置」→「API」中创建）
- 没装 OpenList 也能用：连不上时自动改用本地磁盘，界面标注「本地存储（降级）」，
  之后填上地址即可无缝切换
- `OPENLIST_ROOT` 填 OpenList 里的绝对路径；如果它不在账号的基础路径之内，
  面板会明确提示权限不足
- **不登录也能看**：登录页提供「以游客身份浏览」
  - 没有配置 OpenList 时，游客是这台服务器上的**只读**访客：可以浏览、搜索、打开笔记，
    任何写入（新建 / 编辑 / 移动 / 删除）都会在服务端被拒绝，界面上会标注只读
  - 配置了 OpenList 时，游客用 OpenList 自己的匿名访问权限（公开目录可读）
  - 默认开启；**设置 → 访问 → 允许游客只读浏览**可以关掉，关掉时会同时登出正在浏览的游客

## 安装与卸载

**要求**：systemd 的 Linux 发行版，root 权限，能访问 npm 源。

### 安装

配置写在项目目录的 `.env` 里：

```bash
git clone https://github.com/Moistrocic/notes-manager-web.git
cd notes-manager-web
cp .env.example .env      # 端口、OpenList 地址、管理员账号都在这里
vi .env
sudo ./scripts/install.sh
```

脚本会装好 Node、把程序拷到 `/opt/notes-manager`、构建、写配置、注册并启动 systemd 服务，
最后打印访问地址与账号密码。更多参数见 `sudo ./scripts/install.sh --help`。

**安装后要改配置，改的是运行时那一份**（默认 `/opt/notes-manager/.env`），
不是项目目录里的 `.env`。它的位置在安装结束的摘要、服务启动日志、
以及界面「设置 → 服务器配置文件」里都能看到：

```bash
sudo nano /opt/notes-manager/.env
sudo systemctl restart notes-manager
```

### 设置所有人的默认背景（可选）

分两步：把文件放上服务器，然后在界面里选它。

**第一步：把文件放进数据目录下的 `backgrounds/`**（默认 `/var/lib/notes-manager/backgrounds/`）：

```
/var/lib/notes-manager/backgrounds/
├── scene.pkg          场景壁纸（Wallpaper Engine 的 .pkg）
├── *.jpg / *.png      图片
└── *.mp4 / *.webm     视频
```

**第二步：用管理员账户登录 → 设置 → 默认背景**，在那里选择：

- **种类**：不设置 / 主题极光 / 图片 / 视频 / 场景壁纸——选哪种，下面就出现哪种的参数；
- **文件**：列表就是 `backgrounds/` 里的文件（只列与种类相符的）；放好文件后点「重新读取」刷新；
- **参数**：模糊、暗度、取景区（框住的部分会填满屏幕）；场景壁纸另有「实时渲染」开关，
  关掉时整套部署只送出一张合成好的静态图；
- **备注**：一句话说明这张图的来历。

保存后立即对所有人生效，不需要重启服务。

- 数据目录默认是 `/var/lib/notes-manager`（`--data` 可改），安装脚本会创建并纳入备份
  范围；它不在代码目录里，所以更新程序不会动到它；
- 背景**只在服务器上读取并原样送出**，不需要上传到任何地方；文件不会被复制进代码目录，
  也不会写进仓库；
- 用户界面上的「**使用管理员设置的默认背景**」开关**默认打开**，此时界面上的背景选项
  不显示，取景区、模糊、暗度与是否实时渲染都以管理员的设置为准；**用户可以自己关掉**，
  关掉后就能自由选择极光、本地图片或本地场景壁纸；
- 早期版本用 `backgrounds/background.json` 指定文件；升级后它会被**自动导入一次**
  并改名为 `background.json.imported`，之后一切以「设置 → 默认背景」为准。

#### 关于场景壁纸的获取

项目**不分发**任何壁纸素材。场景壁纸需要你在 Steam 创意工坊**订阅**后自行取得

```
<Steam 库>/steamapps/workshop/content/431960/3691554683/scene.pkg
```

把它复制到上面的 `backgrounds/` 目录即可。壁纸版权归其作者所有。

### 第三方项目

场景壁纸（`scene.pkg`）的容器解析、纹理解码与渲染使用了
[**wallpaper-scene-layers**](https://github.com/Moistrocic/wallpaper-scene-layers)
（MIT 许可）——本项目作者自己维护的库，不在 npm 上，所以工作区直接依赖它这个目录。

它通过 **git 子模块**引入到 `web/src/lib/wallpaper-scene-layers`：

```bash
git submodule status                                    # 当前签出的提交
git ls-tree HEAD web/src/lib/wallpaper-scene-layers     # 本仓库钉住的提交
```

因此克隆时必须带上子模块：

```bash
git clone --recursive https://github.com/Moistrocic/notes-manager-web.git
```

本项目的其余部分均为自有实现。
